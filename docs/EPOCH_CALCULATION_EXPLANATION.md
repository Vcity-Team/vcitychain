# Epoch 计算方式说明

## 核心结论

**Epoch 是基于区块高度计算的，不是基于时间（如夜间0点）**

## Epoch 计算逻辑

### 1. Epoch 大小计算

```go
epochSize = epochDuration / blockTime
```

根据配置文件：
- `dpos_epoch_duration: "300s"` （300秒）
- `block_time_s: 3` （3秒一个区块）

**Epoch 大小 = 300 / 3 = 100 个区块**

### 2. Epoch 编号计算

```go
// 从共识切换高度开始计算
dposBlockNumber = blockNumber - consensusSwitchHeight
epochNumber = (dposBlockNumber / epochSize) + 1
```

### 3. Epoch 边界计算

**Epoch 1 的区块范围：**
- 第一个区块：`共识切换高度`
- 最后一个区块：`共识切换高度 + epochSize - 1 = 共识切换高度 + 100 - 1`

**Epoch 2 的区块范围：**
- 第一个区块：`共识切换高度 + 100`
- 最后一个区块：`共识切换高度 + 200 - 1`

## 关键问题：Epoch 1 的最后一个区块是什么时间？

### ❌ 错误理解
- Epoch 1 的最后一个区块是夜间0点

### ✅ 正确理解
- Epoch 1 的最后一个区块是第 `(共识切换高度 + 99)` 个区块
- 这个区块的实际时间戳取决于它出块的时间
- **不是固定的夜间0点，而是基于区块高度**

### 示例

假设：
- 共识切换高度 = 1000
- Epoch 大小 = 100 个区块
- 区块时间 = 3秒

**Epoch 1：**
- 第一个区块：区块 #1000
- 最后一个区块：区块 #1099
- 如果区块 #1000 在 `2024-01-01 10:30:00` 出块
- 那么区块 #1099 大约在 `2024-01-01 10:34:57` 出块（100个区块 × 3秒 = 300秒 = 5分钟）

**Epoch 2：**
- 第一个区块：区块 #1100
- 最后一个区块：区块 #1199
- 如果区块 #1100 在 `2024-01-01 10:35:00` 出块
- 那么区块 #1199 大约在 `2024-01-01 10:39:57` 出块

## 提案和 Epoch 的关系

### 提案的结束时间

提案有两个时间概念：

1. **投票期结束（EndBlock）**
   - 基于区块高度，不是基于时间
   - 计算：`EndBlock = StartBlock + VotePeriod`

2. **有效期结束（ValidEndBlock）**
   - 基于区块高度，不是基于时间
   - 计算：`ValidEndBlock = StartBlock + ValidPeriod`

### 提案在 Epoch 边界生效

如果提案设置了 `EffectiveEpoch`，它会在指定 Epoch 的最后一个区块（epoch 结束区块）生效：

```go
// 在 epoch 结束区块应用提案
if isEpochEnd && prop.Schedule.EffectiveEpoch == currentEpoch {
    // 应用提案
}
```

## 总结

1. **Epoch 是基于区块高度计算的，不是基于时间**
2. **Epoch 1 的最后一个区块不是夜间0点，而是第 `(共识切换高度 + epochSize - 1)` 个区块**
3. **Epoch 的实际时间取决于区块的出块时间，不是固定的时间点**
4. **提案的结束也是基于区块高度，不是基于时间**

## 如果需要固定时间点的 Epoch

如果希望 Epoch 在固定时间点（如夜间0点）结束，需要：

1. **调整共识切换高度**：让第一个 Epoch 的第一个区块在夜间0点出块
2. **或者实现基于时间的 Epoch 计算**：修改 epoch 计算逻辑，基于时间而不是区块高度

但当前实现是**基于区块高度的**，这样更简单、更可靠，不依赖系统时间同步。
