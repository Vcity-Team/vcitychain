# 交易池配置验证方法

## 问题描述

配置已修改为：
```yaml
tx_pool:
  max_slots: 16384
  max_account_enqueued: 1024
```

但仍然遇到 `maximum number of enqueued transactions reached` 错误。

## 可能的原因

### 1. 节点未重启（最可能）

**问题**：YAML配置更改需要**重启节点**才能生效。

**验证方法**：
- 检查节点是否在修改配置后重启
- 如果未重启，配置仍然是旧值（默认值：128）

---

### 2. 配置未正确读取

**验证方法**：查看启动日志，查找交易池初始化相关的日志。

**预期日志位置**：
- `server/server.go:580-592` - txpool创建时
- 但目前代码中**没有日志输出配置值**

---

### 3. 压测速度过快

**问题**：即使配置为1024，如果压测发送速度超过处理速度，队列仍然会满。

**场景**：
- 每个账户最多1024个enqueued交易
- 如果压测每秒发送1000个交易，但出块速度是每3秒一个区块
- 每个区块只能打包有限数量的交易
- 队列仍然会积压并填满

---

## 验证方法

### 方法1：检查启动日志（推荐）

**查看节点启动日志**，查找以下信息：

1. **配置文件路径**：
   ```
   Reading config from: ./node-config-validator.yaml
   ```

2. **交易池初始化**（如果代码中有日志）：
   ```
   Initializing txpool with MaxSlots=16384, MaxAccountEnqueued=1024
   ```

3. **错误信息**（如果配置未读取）：
   ```
   Config error: ...
   ```

---

### 方法2：使用RPC查询当前配置

**使用PowerShell命令**：

```powershell
# 查询交易池状态
$response = Invoke-RestMethod -Uri "http://127.0.0.1:8545" -Method Post -ContentType "application/json" -Body '{"jsonrpc":"2.0","method":"txpool_inspect","params":[],"id":1}'
Write-Host "当前容量 (slots): $($response.result.currentCapacity)"
Write-Host "最大容量 (max_slots): $($response.result.maxCapacity)"
Write-Host "每个账户最大enqueued交易数 (max_account_enqueued): $($response.result.maxAccountEnqueued)"
```

**返回示例**：
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "pending": {},
    "queued": {},
    "currentCapacity": 0,
    "maxCapacity": 16384,
    "maxAccountEnqueued": 1024
  }
}
```

**说明**：`txpool_inspect` 现在会返回 `maxAccountEnqueued` 配置值，可以验证配置是否正确加载。

---

### 方法3：添加调试日志（需要修改代码）

如果代码中没有日志输出配置值，可以添加：

**文件**：`server/server.go:580-592`

**添加日志**：
```go
m.logger.Info("🔧 初始化交易池",
    "MaxSlots", m.config.MaxSlots,
    "MaxAccountEnqueued", m.config.MaxAccountEnqueued,
    "PriceLimit", m.config.PriceLimit,
)

m.txpool, err = txpool.NewTxPool(
    // ...
)
```

---

## 解决方案

### 方案1：确保节点重启（最重要）

1. **停止节点**
2. **检查YAML配置文件**（确认配置正确）
3. **重启节点**
4. **查看启动日志**（确认配置加载）

---

### 方案2：检查配置传递

**配置传递链路**：
```
YAML文件 (max_account_enqueued: 1024)
  ↓
command/server/config/config.go:ReadConfigFile()
  ↓
params.rawConfig.TxPool.MaxAccountEnqueued = 1024
  ↓
command/server/params.go:225
  ↓
server.Config.MaxAccountEnqueued = 1024
  ↓
server/server.go:589
  ↓
txpool.Config.MaxAccountEnqueued = 1024
  ↓
txpool/txpool.go:216
  ↓
accounts.maxEnqueuedLimit = 1024
```

**验证点**：
- 检查每个环节的日志输出
- 确认配置值是否正确传递

---

### 方案3：降低压测速度

如果配置已生效，但仍然报错，可能是压测速度过快：

**建议**：
- 降低并发数
- 增加交易发送间隔
- 或者进一步增加 `max_account_enqueued` 的值

---

## 快速验证清单

- [ ] 节点已重启
- [ ] YAML配置文件格式正确（缩进、字段名）
- [ ] 配置文件路径正确
- [ ] 启动日志中无错误信息
- [ ] 使用RPC查询当前配置值
- [ ] 压测速度是否过快

---

## 下一步

如果确认配置已正确加载但仍有问题，可能需要：
1. 进一步增加 `max_account_enqueued`（如2048或4096）
2. 优化出块速度（减少 `block_time_s`）
3. 增加区块GasLimit（允许打包更多交易）
4. 检查是否有nonce不连续的问题
