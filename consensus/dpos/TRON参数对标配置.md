## 详细配置建议

### 1. 区块时间配置

**TRON标准**：3秒一个区块

**当前配置**：
```go
// 当前代码中硬编码为2秒
2*time.Second, // 区块时间
```

**建议修改**：
```bash
# 启动参数
--block-time "3s"

# 或在genesis.json中配置
"blockTime": "3s"
```

**代码位置**：
- `consensus/dpos/block_builder.go:312` - 硬编码为2秒
- `consensus/dpos/block_production.go:23` - 默认2秒

### 2. 交易池配置（重点）

**MaxAccountEnqueued（每个账户最大enqueued交易数）**

**TRON对标分析**：
- TRON的TPS约2000-3000
- 每个区块3秒，可以处理约6000-9000个交易
- 假设有1000个活跃账户，每个账户平均需要处理6-9个交易
- 考虑到nonce不连续和网络延迟，建议：**512-1024**

**建议配置**：
```bash
--max-enqueued 1024
```

**计算依据**：
- 3秒一个区块 = 每秒0.33个区块
- 假设每个区块打包1000个交易 = 每秒330个交易
- 如果有1000个账户，每个账户每秒约0.33个交易
- 考虑到网络延迟和nonce不连续，需要缓冲：0.33 * 3秒 * 安全系数(3) ≈ 3个交易
- 但压测时可能更快，所以需要更大缓冲：**512-1024**

### 3. MaxSlots配置（交易池总槽位）

**当前默认**：4096

**建议配置**：
```bash
--max-slots 16384
```

**计算依据**：
- 每个交易占用槽位 = `txSize / 32kB`
- 假设平均交易大小 = 1kB，每个交易占用 1 slot
- 如果支持1000个账户，每个账户1024个enqueued = 1,024,000个交易
- 但考虑到实际使用，建议：**16384**（约16倍当前值）

### 4. 区块GasLimit配置

**TRON对标**：
- TRON每个区块可以打包约1000-2000个交易
- 假设平均每个交易消耗21000 gas（普通转账）
- 1000个交易 = 21,000,000 gas
- 2000个交易 = 42,000,000 gas

**建议配置**：
```bash
# genesis.json
--block-gas-limit 50000000  # 5000万，约可打包2000+个普通转账
```

**当前默认**：5242880（约250个普通转账）

### 5. SR数量配置

**TRON标准**：27个Super Representative

**当前配置**：4个（默认）

**建议配置**：
```bash
# 根据实际需求配置
--dpos-validators-count 27  # 完全对标TRON
# 或
--dpos-validators-count 4   # 保持当前配置（测试环境）
```

### 6. Epoch时长配置

**TRON标准**：6小时一个epoch

**当前配置**：24小时（默认）

**建议配置**：
```bash
# 在genesis.json或配置文件中
"dpos_epoch_duration": "6h"
```

## 参数说明

### 1. MaxAccountEnqueued = 1024

**原因**：
- TRON的TPS高，需要更大的队列缓冲
- 压测时，发送速度可能超过处理速度
- Nonce不连续时，需要更多缓冲空间
- 512-1024是合理的范围

**计算**：
- 3秒一个区块，每秒0.33个区块
- 每个区块1000个交易，每秒330个交易
- 1000个账户，每个账户每秒0.33个交易
- 考虑3倍安全系数：0.33 * 3 * 3 ≈ 3个交易
- 但压测时可能更快，所以需要512-1024

### 2. MaxSlots = 16384

**原因**：
- 支持更多账户和更多交易
- 每个交易平均占用1-2个slot
- 1024账户 * 1024交易/账户 = 1,048,576个交易
- 但实际使用中，不会所有账户都满，所以16384足够

### 3. BlockTime = 3s

**原因**：
- TRON标准是3秒
- 当前代码是2秒，需要改为3秒以完全对标TRON

### 4. BlockGasLimit = 50000000

**原因**：
- TRON每个区块可以打包1000-2000个交易
- 每个普通转账约21000 gas
- 2000个交易 = 42,000,000 gas
- 加上安全余量，建议50,000,000

## 注意事项

1. **区块时间改为3秒**：
   - 需要修改代码中的硬编码（2秒）
   - 或通过配置文件设置

2. **交易池参数**：
   - `max-enqueued`：直接影响压测时的队列满问题
   - `max-slots`：影响整体交易池容量
   - 建议先设置较大值，观察实际使用情况后再调整

3. **性能测试**：
   - 先使用建议值进行测试
   - 根据实际TPS和队列使用情况调整
   - 监控交易池状态，避免过大导致内存问题
